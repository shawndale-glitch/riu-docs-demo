# Decision and gap log

!!! warning "DRAFT"
    Entries marked **Proposed** are not yet agreed.

A numbered record of mapping decisions and gaps. Building-block pages link here (for example `[D-004](decision-log.md#d-004)`) instead of repeating the reasoning, so each decision is explained once and stays findable.

## How to add an entry

1. Take the next free number: `D-nnn` for a decision, `G-nnn` for a gap. Never reuse or renumber an entry.
2. Copy the entry format below into the right section, newest at the bottom.
3. Link to the entry from every building-block page it affects.
4. When a gap is resolved, don't delete it. Set its status to **Resolved** and link the decision that resolved it.

```markdown
### D-nnn: <short title> {#d-nnn}

| | |
|---|---|
| Status | Proposed / Agreed / Superseded by D-nnn |
| Date | YYYY-MM-DD |
| Decided by | <name, role> |
| Affects | <building-block pages> |

**Context.** <What problem or choice came up.>

**Decision.** <What was decided.>

**Consequences.** <What this means for the mapping, the data, or other teams.>
```

For a gap, use `G-nnn`, and replace **Decision** and **Consequences** with **Impact** (what data or behavior is lost) and **Options** (possible workarounds, such as a UDF, a different OPERA Cloud object, or not migrating).

## Decisions

### D-001: Source of truth for field-level mappings {#d-001}

| | |
|---|---|
| Status | Proposed |
| Date | 2026-09-30 |
| Decided by | TBC |
| Affects | All building-block pages |

**Context.** The shell workbooks and these pages both describe field-level mappings. If both are edited by hand, they drift apart.

**Decision.** The workbooks stay authoritative for field-level rows. Field mapping tables on building-block pages are generated from the workbooks by a script, and are not edited by hand. Narrative, transformation rules, gaps, and decisions are written by hand around the generated tables.

**Consequences.** Changes to a mapping row are made in the workbook first, then the tables are regenerated by `tooling/mapping_import.py`. The script depends on the workbooks keeping a stable column layout, which is TBC until the first delivery.

### D-002: Profile creation date is not migrated (sample) {#d-002}

| | |
|---|---|
| Status | Proposed |
| Date | 2026-10-09 |
| Decided by | TBC |
| Affects | [Perfil de huésped to Profile (Guest)](perfil-de-huesped.md) |

**Context.** RUMBO stores the date each guest profile was created (`CLI_FEC_ALTA`). OPERA Cloud sets its own creation date when the profile is loaded.

**Decision.** Sample entry for the demo: the RUMBO creation date is not carried across.

**Consequences.** Reports that rely on "guest since" use RUMBO history until it's archived.
